# Plan: URL linkification + rich embeds

TL;DR: Detect URLs client-side with `linkifyjs`, render them as real anchors via a new token-based `RichText.svelte` (no `{@html}` for message text), and expand supported links into inline embeds ("always load inline") using a curated provider map (Reddit oEmbed, Redgifs direct iframe, YouTube, Imgur, etc.) with the free keyless `noembed.com` aggregator as fallback. Applied to every free-text render site: message bodies, task titles/descriptions/completions, reward titles/descriptions/claims, edge-task reveal prose. Identifier fields (names, emails, passkey labels, thread tags) deliberately excluded.

## Decisions (from user)
- Provider strategy: curated map + noembed.com fallback. No paid services, no API keys.
- Embeds always load inline (no click-to-load gate).
- Scope: everywhere user text appears. Names/emails/tag labels excluded (identifier fields, not prose).
- Detection must be client-side for messages (E2E encryption; server never sees plaintext). Embed metadata fetching is client-side only; plain link rendering works during SSR.

## Steps

Phase 1 — foundation (pure logic)
1. `npm i linkifyjs dompurify` (+ `@types/dompurify` not needed; dompurify ships types).
2. New `src/lib/embeds.ts` (alias-free pure module):
   - `classifyUrl(url)` → `{ kind: 'image' | 'video' | 'provider:<name>' | 'link' }` using linkifyjs's parsed href value. Curated: redgifs (`redgifs.com/watch/<id>` → iframe `https://www.redgifs.com/ifr/<id>`), youtube/youtu.be (→ youtube-nocookie embed URL), imgur single images, reddit (`reddit.com/r/*/comments/*`) → oEmbed fetch, vimeo/spotify/soundcloud/twitter-x → noembed fallback. Only `https:` (and `http:`) allowed; `javascript:` etc. rejected.
   - `oembedEndpoint(url)` → curated endpoint (reddit: `https://www.reddit.com/oembed?url=…`; redgifs not needed, iframe direct) or `https://noembed.com/embed?url=…` for fallback-eligible hosts, else null.
   - Module-level `Map` cache of URL → resolved embed metadata (avoid refetch on invalidate/rerender).
3. Tests `src/lib/embeds.test.ts` (node project): provider classification table, scheme rejection (`javascript:alert(1)`, `data:`), redgifs id extraction, reddit path matching, non-embed hosts return null endpoint.

Phase 2 — rendering components
4. New `src/lib/components/RichText.svelte`: takes `text: string`; uses `linkifyjs` `find(text)` (or tokenize) to split into plain-text and link tokens; renders `{#each}` — plain tokens as escaped text nodes, link tokens as `<a href rel="noopener noreferrer ugc" target="_blank">`. Preserves whitespace via the same `white-space: pre-wrap` styling (pass through class). No `{@html}` in this component. Works in SSR.
5. New `src/lib/components/UrlEmbed.svelte`: given a classified link URL, decides render mode client-side (embed rendering only after mount — no third-party fetches during SSR/prerender):
   - direct image → `<img loading="lazy">` with alt from URL;
   - redgifs / youtube → sandboxed `<iframe>` built from the curated URL (`sandbox="allow-same-origin allow-scripts allow-popups"` minimum needed for player, `referrerPolicy="no-referrer"`, `loading="lazy"`);
   - reddit and fallback hosts → fetch oEmbed JSON (CORS is supported by reddit oEmbed and noembed), render `title`/`provider_name`/`thumbnail_url` plus the returned `html` through **DOMPurify.sanitize with an iframe/embed allowlist** into `{@html}` (the only sanitized `@html` site in the app — comment why at the site, per repo habit).
   - Failed/blocked fetch → silent fallback to plain link (no console noise — the e2e fixture fails on console errors).
6. `RichText.svelte` renders at most one embed: the **first** supported URL in the text becomes an embed; remaining URLs stay anchors. Comment why (layout sanity in a chat bubble).

Phase 3 — integration
7. `src/lib/components/MessageBubble.svelte`: replace `<p class="text">{payload.text}</p>` with `<RichText text={payload.text} />` inside the same conditional; keep ciphertext-never-rendered tests passing.
8. Same swap in: `ManagedTaskList.svelte` (title + description), `TaskCompletionList.svelte` (taskTitle/taskDescription/completionMessage), `RewardList.svelte` (title + description), `EdgeTask.svelte` (`displayText.text`). Titles: linkify only (no embeds in headings) — pass a `maxEmbeds={0}` prop. Also reward-claim history lines (titles, linkify only).
   - Excluded: partner/user names, emails, passkey names, thread tags, attachment fileNames, reaction emoji, guide titles.

Phase 4 — tests, docs, verification
9. Component tests: `RichText.svelte.test.ts` (jsdom) — tokens render, anchors have correct href/target/rel, `javascript:` URLs render as text not links, script-tag-looking input stays inert; `UrlEmbed.svelte.test.ts` (jsdom, mock global fetch) — redgifs iframe src, reddit oEmbed sanitized html rendering (assert `<script>` stripped), fetch-failure falls back to link. Update `MessageBubble.svelte.test.ts` for the new inner structure.
10. e2e: add a block to `e2e/messaging.spec.ts` — send a message containing a redgifs and a reddit URL; stub network with `context.route` fulfilling noembed/reddit oEmbed stubs (fixture fails on console errors — real network calls must not happen or must be stubbed); assert iframe/title render and that links open (or just presence).
11. Docs: new `docs/embeds.md` (provider map, security model, noembed fallback, cache) + row in AGENTS.md doc table; update `docs/messaging.md` (message bodies now render links/embeds). Copy this plan to `docs/historical-plans/2026-09-15-embeds.md`.

## Decisions
- Noembed.com fallback (free, keyless, CORS-enabled) covers ~200 providers with zero maintenance.
- Redgifs uses the documented `redgifs.com/ifr/<id>` iframe directly — no API call, no key.
- Reddit uses its public oEmbed endpoint (no key).
- First-URL-only embed per text block.
- DOMPurify-sanitized `{@html}` is confined to oEmbed `html` field inside `UrlEmbed.svelte`.
- No server-side proxy route: keeps encryption invariants intact and avoids Workers egress for third-party fetches.

## Further considerations
1. noembed.com has no SLA — if it degrades, failures already fall back to plain links silently; could later swap in a self-hosted oEmbed proxy on the Worker.
2. Redgifs/reddit iframes leak viewer IP by design of "always load inline" (user's choice) — documented in docs/embeds.md so the tradeoff is recorded.
3. If embeds feel heavy in task lists later, `maxEmbeds` prop already allows zeroing them per site without code changes.
